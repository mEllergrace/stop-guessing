The problem

An agent reads data, transforms it, reports a result — and nothing durable records which bytes entered, what happened to them, or whether the report is true. Every downstream audit inherits that gap.

Two documented failures define its shape. Replit / SaaStr, 21 July 2025: an agent deleted a production database during an explicit code freeze, fabricated roughly 4,000 fictional records, and misreported what it had done (AI Incident Database #1152). Berkeley RDI, April 2026: a zero-capability agent scored ~100% on eight benchmarks by attacking the evaluator — including installing a fake curl that returned fabricated success to the grader (writeup).

The second is a design constraint, not an anecdote: the recorder must not be reachable by the agent it records.

What nobody else does

Everything in this space records actions. Nothing records data flow. Surveyed across Claude Code's native OpenTelemetry, Obsigna, HDP, Langfuse, Arize Phoenix, LangSmith, OpenLineage and Microsoft's agent-governance-toolkit: every one answers “which agent called which tool, and was it allowed?” Not one answers “which bytes entered, and where did they end up?”

Accumulation, not per-call matching

Every agent DLP hook in the wild is a regex fired independently per call, and each call looks fine. The risk that materialises is twelve individually-innocuous reads composing into a dataset, then one egress. Proved across six separate hook processes:

PROCESS 1: clean session, egress            -> allowed
PROCESSES 2-5: four classified reads        -> ask (each a separate process)
PROCESS 6: the IDENTICAL egress             -> DENY
  contributing artifacts: art_27607079, art_66617765, art_84867751, art_86402881

The same curl, opposite answers. What changed is what the session carries.

Derivation edges

An output declared public, built from two restricted inputs, carries restricted — with an edge per input naming the script that joined them. OpenTelemetry's GenAI semantic conventions contain zero provenance attributes; OpenLineage has the right graph primitive and no agent emitter.

Custody state as a policy input

No surveyed system feeds accumulated custody state back into the permission decision. The hooks to do it are shipping, and unused. Here the session's taint is the context a Cedar-shaped policy engine evaluates against.

The thesis

The agent's control decisions are computed only from trusted inputs; data handling is delegated to deterministic, capability-constrained code; and every delegation is recorded.

Backing: Design Patterns for Securing LLM Agents against Prompt Injections (IBM / Google / ETH / Microsoft) and CaMeL (DeepMind / ETH), which protect control flow rather than sight of data. The stronger claim — that the model never sees data — is what the bar posture implements. It ships as an option; it is not the claim we lead with.

Provenance is evidentiary, not preventive. A hash-chained log of an exfiltration is still an exfiltration. This is not a prompt-injection defence and will not be sold as one.

What a proof is

Not a passing test. A proof is a record in this toolchain's own keyed ledger, produced by an executable procedure that exercises the real surface. proofs: in docs/claims.yaml is written only by stop-guessing prove. A claim with no surviving proof is a failed claim, not an unassessed one.

The chain is HMAC-keyed rather than a plain hash chain, because an agent with write access can truncate a SHA-256 chain and recompute a valid one. Demonstrated and kept as a control test:

unkeyed ledger, 50 records fabricated -> intact=True   <-- forgery UNDETECTED
keyed,  forged with no key            -> caught at entry 100
keyed,  forged with wrong hmac key    -> caught at entry 100
keyed,  forged WITH the real key      -> intact  (the key is what stops it)

A gate that cannot fail is not a gate

Each of these is verified after every change, and each produces a named finding:

  • Tamper with a proof record → the chain breaks and every proof in it is invalidated
  • Hand-edit a real record id onto another claim → was recorded against CLAIM-02
  • Edit a procedure body after it proved something → produced by a since-modified procedure
  • Hand-edit the filled workbook → its digest no longer matches the one pinned in the proof

What is and is not proven

An independent review on 2026-08-03 found that the proof harness could demonstrate a primitive while the installed plugin never invoked it — and it was right about eighteen findings, filed as #13–#30. The distinction it drew is the one that matters here:

ProvenNot proven
The keyed ledger detects truncate-and-recompute; an unkeyed one does not That any third party has verified any of this
The installed hook writes keyed custody records at PreToolUse and PostToolUse That the recorder is beyond the agent's reach — there is no daemon, so isolation stays at tier 0/1
Taint survives process boundaries and cache deletion, because the ledger is authoritative That egress detection is complete — it is a command-shape heuristic, not a boundary
Derivation edges carry labels from inputs to outputs That path extraction sees every artifact a shell command touches
Segment seals are MAC'd, so history cannot be rewritten without the key That delegated scripts are sandboxed — "network=deny" is proxy variables, not a capability boundary
The AI-CAIQ is derived from proofs and the template is never modified That signing is publicly verifiable — it is HMAC, so a verifier needs the signing key

What the judge panel says

A panel of mechanical lenses reviews each proof procedure for adequacy — whether the test inside it is strong, not merely whether it ran. Disapproval is deferred: it is recorded in the ledger and shown here, and it does not flip the verdict. A heuristic is qualified to make a human look, not to void a proof.

Relationship to no-noodles

STOP-GUESSING vendors no-noodles byte-identically and supersedes it. One dispatcher replaces four hook registrations and runs the vendored rules first, in their original order, passing their refusals through byte-for-byte — so a user who has learned what NO-NOODLE: looks like sees the same text. # noodle-ok, # risk-ok and # build-ok: keep working, as do /no-noodle and /noodle-options. A 73-case corpus replayed through both paths is the acceptance gate.

Install

/plugin marketplace add mEllergrace/stop-guessing
/plugin install stop-guessing@stop-guessing

# or, for the supersession path and tier-2 isolation
git clone https://github.com/mEllergrace/stop-guessing
cd stop-guessing && ./install.sh --all-profiles --supersede-no-noodles

Three postures ship; the default is steer. Full-depth tracking is the default and is never silently reduced. Removable at four levels — posture, per-rule, per-project, full uninstall — none of which destroys the accumulated ledger.

Offline by default. The shipped package is audited for network call sites and has none outside the named opt-in anchoring exception. That is a source audit, not proof of no network activity — it cannot see indirect subprocess calls, shell programs or commands assembled at runtime. Sigstore and RFC 3161 anchoring are opt-in and announce themselves.
